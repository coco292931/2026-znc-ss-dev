# rewrite 控制逻辑不变量

本文记录当前路径跟随控制器的边界。后续精简、调参或合并代码时，应先检查本文，避免因上下文不完整而重新引入互相竞争的寻路逻辑。

## 1. 唯一主链路

```text
摄像头帧
  -> 94x60 最长白列锚定
  -> 实时左右边线、中线、近端/远端误差
  -> PathController 目标速度和目标偏航角速度
  -> IMU 偏航反馈
  -> 左右轮目标速度
  -> 编码器前馈 + PI
  -> PWM
```

- 普通巡线、十字、丢线恢复和电机闭环以提交 `b1756fc` 的行为为基线。
- 新视觉算法只能补充环岛判断；环岛未确认时不得改写普通巡线误差或目标偏航。
- `--topology` / `--cm-error` 引入的连通域拓扑与厘米误差是**纯观测层**（`track_topology.*`）：只在 `RoadEstimateLite` 中产出数据供遥测与自测使用，不进入 `StepInput`，不参与巡线、控制或状态转换。若要把它接入导航判据（例如作为环岛准入旁证），必须先更新本文并补对应自测。
- 可通过修改现有参数解决的问题，不增加第二套参数、控制器或状态。
- `StepInput` 只传导航决策实际使用的数据；轮速和左右累计里程保留在 `MotorFeedbackLite`，不复制到导航输入。

## 2. 符号和物理方向

- 遥测原始 `line_error > 0` 表示图像目标在右侧。
- 当前倒装摄像头通过 `vision_yaw_sign = -1` 完成物理方向转换。
- 控制层正偏航表示右转；右转时左轮目标速度应高于右轮。
- 轨迹坐标为启动方向 `+X`、车辆右侧 `+Y`。
- 正常前进且 `forbid_reverse` 开启时，左右 PWM 均不得为负。
- 更换主板、编码器或电机接线时，只修改既有 sign/swap/flip 配置，不在算法中补反号。

## 3. 状态优先级

1. 持续丢线和失控保护可停车。
2. 已进入的十字、环岛或目标动作先完成自身退出条件。
3. `FOLLOW` 中十字证据优先于环岛候选，环岛优先于目标动作。
4. `--side-road` 关闭时，环岛跟踪不得改变边线、误差、偏航或普通状态。

十字必须由双侧对称开口连续确认。进入 `CROSS_LOCK` 后使用 IMU 锁定进入航向；达到最小距离且双边重新稳定、近远误差回中后退出。单侧开口不是十字。

## 4. 新环岛的接管边界

- `side_open` 仅表示老视觉算法的单侧开口证据。
- `roundabout` 和 `roundabout_stage` 仅表示新环岛识别结果。
- `APPROACH` 全程只观察并继续使用实时普通边线，不修改普通巡线偏航；首个恢复段视为环岛出口，只有同侧第二恢复段连续确认并进入 `INSIDE` 后才允许环岛转向。正式接管仍必须满足 `side_start_distance_cm`，旧 `side_open` 不作为准入条件。
- `APPROACH` 锁存首个恢复点和两侧预测线；短暂缺帧不能清除，只有相反方向证据、十字或既有总超时才能取消。首恢复点已向底部移动后，后续独立出现的上方恢复点可作为第二恢复段。
- 新环岛证据连续达到 `round_enter_frames` 且第二恢复段有效后，视觉阶段才可进入 `INSIDE`；当前赛道测试入口使用 3 帧确认。
- `PathController` 只接受 `INSIDE + 明确左右方向`；不再保存可与阶段矛盾的 `roundabout_valid` 副本。
- 一键启动不把 TOF 瞬时有效或基线就绪作为环岛准入条件；TOF 无数据时仍可由视觉 `INSIDE`、IMU、双编码器和启动距离接管，但已经确认 `ramp_detected` 时必须禁止入环。
- `INSIDE` 使用环岛重建中线；`EXIT` 使用出口重建。出口预测线连续对称后进入 `REACQUIRED` 并清除视觉锁；若 `EXIT` 直接看到对称十字开口，则立即取消环岛视觉状态，让下一帧十字优先接管。
- `INSIDE` 期间目标偏航及实际轮差不得反向；IMU 和编码器同向累计达到 360° 后进入 `EXIT` 航向锁，目标固定为入口原航向，允许小幅反向修正过冲。
- 环岛 `LEFT/RIGHT` 是视觉拓扑方向，只在进入控制前经过一次现有 `vision_yaw_sign` 换算；`APPROACH` 预转、`INSIDE`、`EXIT` 和 IMU 同向锁定必须共用换算后的 `side_direction_`，不得各自补反号。进入和退出期间 IMU 实测若反向，立即提高同向最低偏航；内轮可降到 `0` 但不得反转。
- 环岛进入后至少保持到 IMU 与编码器均沿同方向累计约 `90°` 且持续 `0.5s`，才接受视觉 `EXIT`，避免入口纹理误触退出。环岛速度继续复用 `round_speed_scale`，不增加入口专用速度参数。
- 环岛入口记录连续 IMU 航向和编码器差速航向。两者均完成同方向 360° 后进入出口航向锁；无需等待视觉 `REACQUIRED`，IMU 回到目标航向、编码器确认同方向至少完成一圈且双边主线稳定连续 2 帧后恢复 `FOLLOW`。
- 当前环岛按“绕一圈回到入口航向”的赛道结构锁定；航向容差复用现有 `cross_heading_tolerance_deg`，不增加第二套角度参数。
- 十字证据、坡道门控、IMU/里程门控、启动距离、超时和冷却均可阻止环岛接管。
- 遥测 `side_phase` 为兼容字段，直接由主状态推导：`ROUNDABOUT -> ARC`，`ROUNDABOUT_EXIT -> REACQUIRE`，其他为 `NONE`。

## 5. 运动闭环和降级

- 视觉只生成目标速度和目标偏航角速度，不直接写 PWM。
- IMU 有效时用实测偏航率闭环；S 弯目标达到明确转向量且与实测偏航反向时按跟踪误差增强反馈，微小修正仍保持弱反馈以抑制蛇形。IMU 失效时才使用编码器差速估计并限幅。
- 左右轮各自使用速度前馈和 PI；目标斜坡、积分限幅、PWM 变化率和饱和保护继续有效。小修正保留双轮前进，中强弯开始释放内轮，强弯允许内轮目标降到 `0` 但不得反转。S 弯换向时旧外轮快速释放，刚释放的新外轮以同一受限快速斜率重新接管。
- GUI 和启动入口不限制视觉及偏航增益的人工上限，只拒绝负数和非有限值；实际输出仍受目标轮速、PWM 上限、禁止倒转和失控停车保护约束。
- 失控旋转保护必须区分“同方向且视觉有效的明确大转向”和非预期自旋；前者继续执行，反方向旋转、低转向命令下的高速自旋及双轮超速仍锁停。
- 坡道只在既有 TOF 门控确认且实际轮速低于目标时增加有限动力；加力随视觉目标偏航或轮速接近目标连续淡出，弯道和下坡恢复普通闭环，不能创建独立寻路逻辑。
- 传感器降级只降低速度和反馈能力，不能改变视觉误差的左右符号。

## 6. 修改后的最低验证

```powershell
.\scripts\deploy\deploy_rewrite.ps1 -BuildOnly
```

该入口只执行 GCC 8.3 板端兼容构建，不上传、不启动电机。主机自测不再绑定部署入口；涉及视觉时应按需独立运行合成左右弯、单臂、双臂十字及环岛阶段测试，涉及遥测时应确认已有 CSV 字段名称和含义保持兼容。
